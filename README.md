# snackamusik

A personal album journal: browse records, see cover photography, and read my notes on the music, artwork and favourite tracks. Anyone can read the journal; only the configured administrator email address(es) can add, edit or remove albums.

The website is in Swedish and is intended for a Swedish-speaking audience.

## Stack

- React, TypeScript and Vite.
- Azure Static Web Apps with its integrated Azure Functions API.
- Azure Table Storage for album details; a private Blob Storage container for the original cover images. Images are only returned through the API.
- Static Web Apps built-in Microsoft Entra ID sign-in. The API checks the trusted Static Web Apps principal against `GLOBAL_ADMIN_EMAILS` on every write.
- Bicep provisions the Static Web App, Storage Account and Application Insights. GitHub Actions deploy the app and infrastructure; Azure login uses OIDC federation.

The managed Functions API requires a server-side Storage connection string in its Static Web Apps app settings; it is generated by Bicep and is never sent to the browser or stored in the repository. Shared-key access is enabled on the Storage Account for this managed API integration. Do not expose or commit the key.

Album entries include artist, title, optional release year, format, separate 0–5 scores for the album and artwork, a favourite track, a short text review, and a cover image. Images must be JPEG, PNG or WebP and no larger than 8 MB.

## Local development

Prerequisites: Node.js 20+, npm, Azure Functions Core Tools v4, and Azurite.

1. Install dependencies:

   ```powershell
   npm install
   Set-Location api
   npm install
   Set-Location ..
   ```

2. Install and start Azurite if needed:

   ```powershell
   npm install --global azurite
   azurite --silent --location .azurite
   ```

3. In a second terminal, create local Functions settings and start the API:

   ```powershell
   Copy-Item api/local.settings.example.json api/local.settings.json
   Set-Location api
   npm run build
   func start
   ```

4. In another terminal, start the frontend:

   ```powershell
   npm run dev
   ```

Open the Vite URL. In local development, the API uses in-memory data and a mock admin identity. The local example configures `admin@local.test`; use **Sign in** in the app and enter that address to test the editor. This local identity mechanism is disabled in production. Data in memory is lost when the Functions process restarts.

For local Azure Storage testing, set `STORAGE_MODE=table` and `STORAGE_CONNECTION_STRING` in the untracked `api/local.settings.json`. Keep local credentials out of source control.

Build checks:

```powershell
npm run build
Set-Location api
npm run build
```

## Deploy to Azure

### 1. Configure Azure and GitHub

- Create an Azure resource group.
- Create an Entra app registration/service principal for infrastructure deployment and grant it Contributor on the resource group.
- Configure its GitHub OIDC federated credential with issuer `https://token.actions.githubusercontent.com`, audience `api://AzureADTokenExchange`, and subject `repo:<OWNER>/snackamusik:ref:refs/heads/main`.
- Add repository secrets: `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`, and `SWA_DEPLOYMENT_TOKEN` (after the first infrastructure deployment).
- Add repository variables: `AZURE_RESOURCE_GROUP` and `GLOBAL_ADMIN_EMAILS` (comma-separated sign-in email address(es)). `NAME_PREFIX` is optional and defaults to `snackamusik`.

The Azure login workflow uses OIDC; do not create an Entra client secret.

### 2. Deploy infrastructure

Push an `infra/**` change to `main`, or run **Deploy infrastructure** in Actions. To deploy from a local Azure CLI session:

```powershell
az login
az deployment group create `
  --resource-group <resource-group> `
  --template-file infra/main.bicep `
  --parameters namePrefix=snackamusik globalAdminEmails=<admin-email>
```

Use the resulting `staticWebAppName` output to retrieve the deployment token:

```powershell
az staticwebapp secrets list --name <static-web-app-name> --resource-group <resource-group> --query properties.apiKey --output tsv
```

Save it as the GitHub `SWA_DEPLOYMENT_TOKEN` secret. Push an application change to `main` (or run **Build and deploy application**) to publish the site and API.

Sign in with an address listed in `GLOBAL_ADMIN_EMAILS` to manage journal entries. The built-in `aad` provider is used; no custom identity-provider registration is configured. Configure the email variable before relying on the editor.

## API and access

- `GET /api/albums` and `GET /api/albums/{id}/artwork` are public.
- `GET /api/me` reports the current sign-in state and whether the email is configured as an editor.
- `POST /api/albums`, `PUT /api/albums/{id}`, and `DELETE /api/albums/{id}` require a signed-in identity whose email matches `GLOBAL_ADMIN_EMAILS`. Client-supplied identity or roles are never used.
- Album metadata is stored in the `Albums` table. Cover images live in the private `album-artwork` Blob container; the API checks that each image's byte signature matches its declared type.

Static Web Apps managed Functions currently use a server-side Storage connection string for storage access; the app's browser code only calls the API and never receives storage credentials.
